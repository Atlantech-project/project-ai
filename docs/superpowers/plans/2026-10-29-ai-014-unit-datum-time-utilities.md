## Scope

**In:**

1. **Units** (`common/units.py`). One `Unit` enum holding every value of the DB enums `SpeedUnit`, `VisibilityUnit` and `ConstraintUnit` (`ClassDiagramContext.md` lines 139, 205): `KNOTS`, `METRES_PER_SECOND`, `KM_PER_HOUR`, `NAUTICAL_MILES`, `KILOMETRES`, `METRES`, `PERCENT`, `DEGREES`, `MINUTES`, `TONNES`. Each belongs to a dimension (speed, distance, or a single-unit dimension).
   - `parse_unit(text)`: exact match on the DB value; anything else raises `UnknownUnitError`.
   - `convert(value, from_unit, to_unit) -> float`: exact definitions only (1 NM = 1852 m, 1 kn = 1852 m/h, 1 km/h = 1000 m/h). Different dimensions raise `IncompatibleUnitsError`. Single-unit dimensions only convert to themselves.
2. **Time** (`common/time.py`). Zones come from `zoneinfo.ZoneInfo` backed by `tzdata`, with no OS fallback.
   - `load_zone(name)`: an unknown name raises `UnknownTimeZoneError`.
   - `to_local(utc_dt, zone)`: needs an aware UTC datetime; a naive one raises `ValueError`.
   - `to_utc(local_dt, zone)`: takes a naive local wall time.
     - A time in a spring-forward gap raises `NonExistentLocalTimeError`.
     - A time in a fall-back overlap raises `AmbiguousLocalTimeError`.
     - Both subclass `LocalTimeError`, and the message gives the local time, the zone and the reason.
     - No `fold` or earlier/later option.
   - `shift_interval_utc(shift_date, start_time, end_time, zone) -> (start_utc, end_utc)`: follows `port_shift` (`end < start` means the shift ends the next day; `end == start` raises `ValueError`). Each end is resolved through `to_utc`, so DST errors propagate.
3. **Datum** (`common/datum.py`, a fourth file next to your list; it could live in `units.py` instead if you prefer). `check_datum_consistency(tide_set_datum, channel_datum, berth_datum) -> str` returns the shared datum.
   - `None`, `""` or whitespace-only raises `MissingDatumError`.
   - Values that aren't exactly equal raise `DatumMismatchError`. No case or whitespace normalisation.
   - Both errors subclass `DatumError`, and the message names all three values with their sources: `tide_constituent_set.datum_reference`, `navigation_channel.depth_datum`, `berth.depth_datum`.
   - No datum conversion; the module docstring says conversion depends on DEC-27.
4. **Tooling** (`pyproject.toml`, `uv.lock`):
   - `tzdata` becomes the first runtime dependency, unconditional on every platform. It's added with `uv add tzdata`: a `>=` lower bound like the other entries, with the exact version locked in `uv.lock`.
   - `common` is added to mypy `files` and coverage `source`.
5. **Docs and records:**
   - `common/README.md`: the AI-014 line lists what now exists.
   - The AI-014 task decision is added as Proposed (below).
   - The status record and the `WORK_STATUS.md` row are kept up to date.

## Tests

The tests are written before each module's code (TDD).

- **Units:**
  - every ordered pair within the speed dimension (3×3) and the distance dimension (3×3), against exact expected values;
  - round trips A→B→A within `math.isclose(rel_tol=1e-12)`;
  - every cross-dimension pair raises `IncompatibleUnitsError`;
  - each single-unit dimension converts only to itself;
  - unknown text such as `"knots"`, `"KT"` and `""` raises `UnknownUnitError`.
- **Time:** in `Africa/Cairo`, the reference port's zone (Damietta). The exact transition instants are first read from `tzdata` with a quick check, then hard-coded in the tests.
  - a normal day as the control;
  - a real spring-forward gap raises `NonExistentLocalTimeError`;
  - a real fall-back overlap raises `AmbiguousLocalTimeError`;
  - both are `LocalTimeError`, and the messages contain the local time, the zone and the reason;
  - UTC→local→UTC round trip;
  - a naive input to `to_local` and an unknown zone both raise;
  - day shift (06:00–14:00);
  - **a shift crossing midnight (22:00–06:00) resolves to the next local day**;
  - `end == start` raises.
- **Datum:**
  - three equal values return the value;
  - each single mismatch raises `DatumMismatchError`, and the message contains all three values and sources;
  - `None`, `""` and `"  "` in each position raise `MissingDatumError`;
  - `"LAT"` vs `"lat"` and `"LAT"` vs `"LAT "` are mismatches.
- **Commands**, with actual results reported:
  - `uv sync --all-groups`
  - `uv run pytest`
  - `uv run ruff check .`
  - `uv run ruff format --check .` (CI runs it)
  - `uv run mypy`
  - `uv lock --check`, which matches CI's `--frozen`.

## Risks

- **DST rules change.** Egypt has changed its DST rules several times. Tests pinned to real transitions depend on the locked `tzdata` version, and upgrading it can break them. That's intended: they then flag a rule change.
- **Stdlib shadowing.** `common/time.py` shares a name with the stdlib `time` module. It's safe with absolute imports. Nothing may run a script from inside `common/`, and `common/time.py` itself imports `datetime.time`, not stdlib `time`. This is recorded in the decision.
- **Floating point.** Conversions use `float`. The DB stores `decimal`, so callers that need exact decimals must convert at the boundary. That's noted in the docstring.
- **Layout.** AI-011 may move these modules when it decides OQ-8; the imports would then change.
- **Network.** `uv add tzdata` needs PyPI access. If it fails, I'll stop and report the output.
