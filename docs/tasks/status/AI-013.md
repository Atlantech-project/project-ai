## Deployment risk for AI-090
Workers and MySQL share the port server, so TLS may be off there. PyMySQL 1.2.3 asks for TLS by default, without checking the certificate, so on a server offering TLS the login doesn't use `cryptography`. On a server without TLS, the first login after the server's cache empties raises `AttributeError` inside PyMySQL, even with `cryptography` installed, because `caching_sha2_password_auth` has no final `return`. A later login takes the cached path and works. `test_a_first_login_without_tls_uses_cryptography` is a strict xfail that flags a fixed PyMySQL.

**Backend question:** "Does production/prototype MySQL offer TLS to the worker accounts?" If not, this must be fixed before deployment. The user decided on 2026-11-03: keep `cryptography`, patch no driver. The risk is also noted on AI-090 in the backlog.

- **AI-015:** real seed data with parent rows; the write tests here turn foreign key checks off in the worker session.
- **TLS and `cryptography`:** the user approved keeping the package and recording this behaviour on 2026-11-03, with no driver patch; see the deployment risk above.
- **`update_baplie_file`:** not tied to the worker's own run. AI-032 should bind it.
- **Edge behaviours left as they are:** a `Decimal` or `datetime` inside a JSON column raises and counts as INTERNAL_ERROR, so handlers need a rule. `WriteRefused` is retried like any other internal error. A handler opening a third connection stalls 30 s, then fails.
- **Session state:** a setting a handler changes on its session carries across jobs in the pool. Handlers mustn't change session settings.
- **`recommendations` initial status:** PENDING_REVIEW is Proposed. CT-15 names no status; the evidence is DEC-06, CT-10 and the CT-20 example. Backend to confirm.
- **Schema copy behind the Backend:** backend migration `2026_11_03_183535_alter_port_settings_add_min_max.php` adds `min_value` and `max_value`, but PortHub's `schema.sql` hasn't been regenerated. The user agreed on 2026-11-04 to keep the copy at `b4d2deb` and refresh it when PortHub regenerates the file.
- **Stale mirror:** CI can't notice a newer PortHub schema until someone refreshes the mirror.
