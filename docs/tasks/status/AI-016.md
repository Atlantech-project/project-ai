## Summary of the change
- **Workflow:** `.github/workflows/ci.yml` runs on every push and every pull request, plus manual dispatch, with no path filters. `permissions: contents: read`. Actions are pinned to commit SHAs: checkout v7.0.1, setup-uv v10.3.2, upload-artifact v7.0.2.
  - **Jobs:** `lint`, `typecheck`, `tests` (MySQL 8.4 and Redis 7.4 services), `secret-scan`, and `ci-ok`.
  - **`ci-ok`** runs with `if: always()` and fails unless all four needed jobs report `success`, so failure, cancellation, skipping or a missing job all fail it.
  - **Concurrency:** a newer run cancels an older one on PRs and feature branches. Pushes to `develop`, `main` and `release` get one group per commit, so every merge commit there runs to the end.
  - **Two `ci-ok` checks per PR commit:** one from the push run (the branch head) and one from the pull_request run (the merge ref). This is accepted with the "every push and every PR" triggers; it doubles Actions minutes.
- **Tooling:** `pyproject.toml` (not packaged, `requires-python = ">=3.14,<3.15"`), `.python-version` (`3.14`), `uv.lock` (18 third-party packages plus the project itself).
  - Dependency groups: `test` (pytest, pytest-cov, PyMySQL, redis-py), `lint` (ruff, mypy, types-pymysql), and `dev` (both).
  - No runtime dependencies.
- **Tests:**
  - `tests/support/services.py`: service settings from the environment. It is the only non-test code, and test support, not worker logic.
  - `tests/unit/` holds 10 tests (6 functions, one parametrised ×5); `tests/integration/` holds 5 smoke tests:
    - MySQL is 8.4;
    - the session time zone is `+00:00`;
    - the database is `utf8mb4` / `utf8mb4_0900_ai_ci`;
    - the session's client, connection and results character sets are `utf8mb4`, and its collation is `utf8mb4_0900_ai_ci`;
    - an unprefixed Redis key is FIFO under RPUSH/BLPOP.
  - Locally, integration tests skip when no service setting is present. Any partial configuration raises an error naming the missing keys. With `ATLANTECH_REQUIRE_SERVICES=1` (set in CI) a missing service fails them.
  - Connection retries (30 × 1 s) apply only while a service is starting: MySQL errors 2003 and 2013, and Redis connection or timeout errors. Access denied and other errors fail at once with their real cause.
  - **Charset (plan Task 5 choice):** no `ALTER DATABASE` and no `docker run` step. The MySQL 8.4 image defaults are used and asserted, and PyMySQL with `charset="utf8mb4"` negotiates `utf8mb4_0900_ai_ci` (checked against MySQL 8.4.13).
- **Scope:**
  - Ruff excludes `.claude/` (the skill tooling is not AI code).
  - mypy scope: `files = ["tests"]`.
  - Coverage source: `tests/support`.
  - Each module directory joins these scopes when it gains code.
- **Docs and records:**
  - README: "Getting started" (uv, local commands, local Docker services) and a new "CI" section.
  - `Proposed` AI-016 entry in the "AI task decisions" section of `docs/ref/ATLANTECH_Decisions.md`.
  - `.gitignore`: the Python environment, caches and test output.
  - `WORK_STATUS.md` row.
  - Focused correction of SETUP-002 to DONE (PR #4 is merged as `ea51824`), on the user's instruction.
- **Not added:** the planned `.gitleaks.toml`. No allowlist is needed (see the secret scan below), and an empty config would only restate the defaults.
